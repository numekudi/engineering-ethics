# 02 — ダークパターン／反ユーザ設計カタログ

ダークパターン・ハンター用。近年問題化した「ユーザーに害を与える設計判断」（退会妨害、
誤解を招く表示、無同意の計測など）を狙って検出する。これらは主に**原則1（公共性）**・
**原則3（製品）**・**原則6（専門職）**への違反として findings 化する。

重要: `scan` コマンドの候補は出発点にすぎない。ここでは**実 UI・実装・文言・フロー**を読み、
「ユーザーが十分な情報のもとで自由に選べるか」を基準に判断する。判断に迷うときは
「最も弱い立場のユーザーが不利益を被るか」で決める。

## A. 退会・解約・削除の妨害（Roach Motel）
入るのは簡単／出るのは困難、の非対称。
- 退会・解約導線が階層深く隠されている、検索に出ない、電話/来店限定。
- 解約ボタンが `display:none` / 極小 / 低コントラスト / 無効化されている。
- 「本当に退会しますか」を過剰に繰り返す、引き止めの多段ゲート。
- アカウント削除やデータエクスポートを提供しない／実質不能。
→ 該当項目: 1.03, 1.06, 6.07

## B. 誤解を招く表示・不当表示（Deceptive / Bait-and-Switch）
- 「無料」表示だが実際は自動課金・トライアル後課金の開示が不十分。
- 総額・手数料・定期課金の条件を最終段階まで隠す（drip pricing）。
- 機能・性能・安全性について誇大・虚偽の説明。
→ 該当項目: 1.06, 6.07

## C. 同意の擬制・強制（Forced / Pre-selected Consent）
- オプトイン（メルマガ・データ提供・第三者共有）が事前チェック済み。
- 同意しないと本来無関係な機能まで使えない抱き合わせ。
- Cookie/トラッキング同意で「拒否」を著しく不利・困難にする。
→ 該当項目: 3.12, 1.06

## D. Confirmshaming / 誘導文言
- 拒否選択肢の文言で利用者を貶める（「いいえ、私は損をしたい」等）。
- デフォルトや視覚的強調で望ましくない選択へ誘導（misdirection）。
→ 該当項目: 1.06

## E. プライバシー侵害・無同意の計測
- 同意なきトラッキング・フィンガープリンティング・位置取得。
- 個人情報・機微情報（パスワード、カード番号、メール等）のログ出力・第三者送信。
- 収集目的・範囲の不開示、過剰収集。
→ 該当項目: 3.12, 3.13, 1.03

## F. 安全性の毀損
- TLS/証明書検証の無効化、暗号の無効化・自作暗号。
- 認証情報・秘密鍵のハードコード、平文保存。
- 既知の脆弱性を放置、危険な `eval`/動的実行、入力の無検証。
→ 該当項目: 1.03, 2.05, 3.05, 3.10

## G. ナグ／強制継続・自動更新
- 執拗な通知・許可要求の反復（nagging）。
- 自動更新・自動課金の事前十分な告知やワンクリック解約の欠如。
→ 該当項目: 1.06, 3.01

## H. アクセシビリティ排除
- 支援技術で操作不能、コントラスト不足、キーボード操作不能。
- 経済的・地理的・言語的弱者を不当に排除する設計。
→ 該当項目: 1.07, 8.07

## findings 化のルール
- 必ず該当する UI/コード/文言の `file:line` と引用を証跡に付ける。
- 「気に入らない設計」ではなく「ユーザーが害される／自由な選択を奪われる」ことを示す。
- 反証可能性を意識する（Step 2 で攻撃される前提で、証拠の強さを自己評価する）。
