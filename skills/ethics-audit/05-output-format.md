# 05 — 出力様式（レポート＋ツイート）

Step 4 の提示フォーマット。数値は必ず `lib/cli.js score` の出力（AuditResult）を使う。

## 監査レポート（日本語）

```
# 技術者倫理 監査レポート: <リポ名>

総合スコア: <overall>/100 　判定: <合格|要改善|不適合>
確定所見: <totalFindings>件（critical <n> / high <n> / medium <n> / low <n>）
対象: <走査ファイル数> / 監査日: <YYYY-MM-DD>

## 原則別スコア
| 原則 | スコア | 確定所見 |
|------|-------|---------|
| 1. 公共性 | XX/100 | n |
| …（8原則すべて） | | |

## 重大な所見（critical / high）
### [critical] <綱領項目ID> <一言タイトル>
- 場所: `path/to/file.ts:42`
- 証跡: `> 該当コードや文言の引用`
- 問題: 誰がどう害されるか（公共の利益の観点で）
- 綱領: <項目IDと該当趣旨>
- 是正案: 具体的なアクション

（medium / low は要約表でまとめてよい）

## 棄却された主な指摘（透明性）
- <所見> — 棄却理由（例: テストコードだった／文脈上リスクなし／grandstanding）

## 総評
- 最も注力すべき原則と、次の一手（優先度順に2〜3件）。
- 良い点も公正に記す（誇張しない）。
```

### 様式の約束
- **全確定所見に `file:line` と引用**を付す。証跡の無い指摘は載せない。
- スコア・判定は CLI 出力のまま。手で丸めたり忖度したりしない。
- 断定は証跡の範囲に留める。不確実さは「不確実」と書く（RINRI: 誠実さ）。
- 対象は自リポ。第三者リポを一方的に断罪する文体にしない。

## ツイート下書き
`lib/cli.js tweet --input <audit.json> --label <リポ名> --format text` の出力（本文＋
intent URL、`#技術者倫理チェックskill`）をそのまま提示する。本文例:

```
🛠️ <リポ名> の技術者倫理 自己監査
総合 83/100・判定: 要改善
要注力: 1.公共性（28/100）
#技術者倫理チェックskill
```

- これは**自己監査結果の自己開示**である旨を添える。他者糾弾には使わない。
- 投稿するかはユーザーの判断。URL を開くと投稿画面が開くだけで、自動投稿はしない。

### intent URL を絶対に省略しない（重要）
`tweet` が出力した URL は **CLI の出力そのままを1行で・全文**提示すること。次を厳守する:
- `...` や「（中略）」で**短縮しない**。末尾（`#技術者倫理チェックskill` のエンコード）まで載せる。
- URL の**途中で改行しない**（1本の連続した行として出す）。
- パーセントエンコードを**復元・整形しない**（URL はそのまま、本文はデコード版を別途併記）。
- 提示前に、貼った URL が `tweet` の stdout と文字数まで一致するか自己確認する。途中で切れて
  いたら、省略なしの完全な URL を貼り直す。

URL が長いのは正常（本文が全て URL エンコードされているため）。長さを理由に縮めないこと。
